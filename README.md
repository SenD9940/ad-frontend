# United Ad 프론트엔드

팀별 워크스페이스, 멤버 초대·관리, Meta 광고 자산 연결과 캠페인·성과 조회, 네이버 스마트스토어·아임웹 연결을 제공하는 React 애플리케이션입니다.
React 19, TypeScript, Vite, React Router, styled-components, Axios를 사용합니다.

## 실행

Node.js와 npm을 준비하고 `ad-frontend` 디렉터리에서 실행합니다.

```sh
npm ci
npm run dev
```

개발 서버 기본 주소는 `http://localhost:3400`입니다.
`strictPort: true`로 고정되어 있어 `3400`이 이미 사용 중이면 실행 오류를 표시합니다. 같은 프로젝트의 개발 서버가 중복 실행 중인지 확인하고 하나만 실행하세요. `3401` 등 다른 포트로 자동 변경되지 않습니다.
개발 설정은 `/admin-api` 요청을 `http://localhost:8481`로, `/api`와 `/open-api` 요청을 `http://localhost:8480`의 백엔드로 프록시합니다.
로그인·가입·워크스페이스 기능을 실제로 사용하려면 백엔드가 실행되어 있어야 합니다.

## 환경 변수

필요한 값은 프로젝트 루트의 `.env.local`에 설정합니다.

```dotenv
VITE_API_BASE_URL=
VITE_ADMIN_API_BASE_URL=
VITE_API_ORIGIN=http://localhost:8480
```

| 변수 | 용도 |
| --- | --- |
| `VITE_ADMIN_API_BASE_URL` | 관리자 API 기본 주소. 비워 두면 현재 origin의 `/admin-api`를 사용합니다. |
| `VITE_API_BASE_URL` | 일반 API 요청과 토큰 갱신의 기본 주소. 비워 두면 현재 origin의 상대 경로를 사용합니다. |
| `VITE_API_ORIGIN` | Meta 인증 시작 요청이 직접 호출할 API origin. 개발 기본값은 `http://localhost:8480`입니다. |

Meta 인증 시작 요청에는 쿠키를 포함하므로 서버의 CORS·쿠키·OAuth 콜백 설정도 필요합니다.
`VITE_` 변수는 브라우저 코드에 노출되므로 비밀 키를 넣지 않습니다.

## 주요 구조

```text
src/
  api/                 API 요청, 토큰 갱신, 오류 처리
  auth/                인증 컨텍스트와 세션
  admin/               별도 관리자 인증·회원·공간·연결·감사·기술 지원 화면
  support/             고객 승인 및 제한된 지원 화면 접속
  studio/              고객 AI 템플릿·이미지·상세페이지 생성과 결과 조회
  components/          레이아웃, 인증 및 공통 UI
  hooks/               화면별 요청·폼·상태 관리
  pages/               랜딩, 로그인, 가입, 워크스페이스 화면
  styles/              공통 테마와 전역 스타일
  types/               API 및 도메인 타입
```

공개 페이지와 작업 화면은 서로 다른 레이아웃을 사용합니다.
Meta, 네이버 스마트스토어, 아임웹 연동을 제공하며 Threads·Coupang은 준비 중입니다.
워크스페이스에 들어가거나 사이드바의 **Meta**를 누르면 저장된 광고 계정이 있는 경우 성과 화면이 바로 열립니다. 아직 광고 계정을 저장하지 않았다면 자산 편집 화면에서 연결·선택을 진행합니다.
성과 화면 상단의 **자산 편집**에서 별도로 자산을 관리하며, **저장하고 성과 보기**를 누르면 저장된 광고 계정의 성과 화면으로 돌아옵니다. 페이지·프로필만 저장한 경우에는 광고 계정 선택 안내와 함께 편집 화면에 머뭅니다.
전체 광고 계정의 성과는 통화별 합계·일평균으로 표시합니다. CTR·CPC·CPM·ROAS는 서버가 전체 합계로 계산한 값을 사용하며 통화 간 금액을 합산하지 않습니다.
Meta가 노출·클릭을 제공하지 않으면 해당 수치·일평균·관련 비율을 `—`로 표시하고, 광고비·구매금액·ROAS 등 정상 지표는 유지합니다. 일부 계정의 지표가 누락된 전체 합계도 `—`로 표시하며 누락을 0으로 간주하지 않습니다.
전체 요약·광고 계정·캠페인에 구매 전환 금액과 ROAS를 표시합니다. ROAS는 배수(`3.5` → `3.5배`, 350%)이며 지출이 0인 경우 `—`로 표시합니다. 일평균 전환은 지출·노출·클릭에만 적용하며 구매 전환 금액과 ROAS는 기간 기준을 유지합니다.
구매 전환 금액은 Meta가 보고한 구매 전환 가치입니다. 쇼핑몰 전체 매출과 다르며, 구매 추적·전환 가치 설정에 따라 구매 전환 금액이나 ROAS가 0이어도 실제 구매가 없었다는 의미는 아닐 수 있습니다.
조회 기간은 시작일·종료일을 포함해 최대 366일입니다. 계정별 현지 시간대를 따르며 성과가 없는 날도 일평균 계산에 포함합니다.
성과 화면은 `MetaPerformancePage.tsx`, `MetaPerformanceUI.tsx`, `useMetaAdPerformance.ts`, `api/metaAds.ts`에서 관리합니다. 새 인증이나 프론트엔드 환경 변수 없이 기존 저장 자산의 내부 ID와 서비스 인증을 사용합니다.
성과 화면의 **광고 등록**에서 트래픽·판매 목표의 단일 이미지 광고를 등록할 수 있습니다. 같은 Meta 연결에 저장된 광고 계정·Facebook 페이지와 선택적 Instagram 프로필을 사용합니다. 판매 목표는 픽셀 ID가 필요하며, 예산은 계정 통화의 최소 단위 정수로 입력합니다.
광고 이미지는 JPEG·PNG 파일을 선택해 업로드하거나 **URL 입력**을 사용할 수 있습니다. 파일은 최대 10MiB, 각 변 10,000px·총 2,500만 픽셀까지 허용하며 업로드 진행률과 로컬 미리보기를 제공합니다. 업로드 이미지는 `image_key`만, 외부 이미지는 `image_url`만 광고 생성 요청에 전달합니다. 업로드 키는 광고 계정에 귀속되며 계정을 바꾸면 선택을 초기화합니다.
광고 계정을 선택하면 해당 계정의 `promote_pages`를 조회합니다. 저장된 페이지도 현재 계정에서 사용할 수 있을 때만 선택할 수 있으며, 새 페이지는 **페이지 저장하고 계속**으로 추가합니다. 페이지 선택·저장 후 내부 페이지 ID를 사용해 등록 폼이 열립니다. 조회되는 페이지가 없으면 자산 할당·접근 권한·재인증을 안내하며, 조회·저장 오류는 각각 다시 시도할 수 있습니다. 백엔드는 페이지 저장 시와 광고 생성 직전에도 해당 계정에서 사용 가능한지 다시 확인합니다.
등록 내용을 확인한 뒤 캠페인·광고세트·소재·광고를 생성하며 상태는 일시정지입니다. 기존 토큰에 `ads_management` 권한이 필요합니다. 부분 실패·결과 불명 응답의 생성 ID를 보존하고 자동 재시도하지 않습니다.
성과 화면의 **광고 수정**, 캠페인 행의 **수정**, 광고 생성 완료 화면의 대상별 수정 링크에서 이름·활성/일시정지 상태를 변경할 수 있습니다. 광고세트·캠페인은 기존 일 예산도 변경할 수 있습니다. 저장된 광고 계정의 내부 자산 ID와 대상의 Meta 숫자 ID를 사용하며, 일반 수정 화면에서는 대상 ID를 직접 입력합니다.
선택한 항목을 검토한 뒤 해당 대상 하나만 PATCH합니다. 광고세트의 공유 예산과 캠페인 예산 관리 제한, 상위 상태에 따른 게재 조건을 안내합니다. 수정 요청은 자동 재전송하지 않으며 결과가 불확실하면 Meta 광고 관리자에서 확인한 뒤 다시 진행합니다. `MetaAdEditPage.tsx`, `api/metaAdUpdates.ts`, `types/metaAdUpdate.ts`에서 관리합니다.
광고 등록은 `MetaAdCreatePage.tsx`, `MetaPageSetup.tsx`, `useMetaAdPages.ts`, `MetaAdCreationForm.tsx`, `metaAdFormModel.ts`, `api/metaAdCreation.ts`, `api/metaAdPages.ts`에서 관리합니다. 캠페인만 생성하는 API 래퍼도 제공하지만 등록 화면은 전체 광고 생성 API를 사용합니다.
이미지 업로드는 `MetaAdImageInput.tsx`, `api/metaAdImages.ts`에서 관리합니다. 백엔드의 계정별 `/images`에 `multipart/form-data`의 `file`로 전송하며 S3 서명 URL은 광고 요청에 저장하지 않습니다. 생성 시 서버가 이미지 키를 확인하고 새 서명 URL을 발급합니다. 업로드는 자동 재전송하지 않으며, 화면의 선택 해제는 서버 파일 삭제를 요청하지 않습니다.
네이버 검색광고와 상품·주문 변경은 현재 지원 범위에 포함하지 않습니다.
네이버 연결은 커머스ID 팝업을 이용한 간편 연결과 기존 앱 ID·시크릿 입력을 지원합니다. 솔루션마켓 미등록·서버 설정 미완료 상태에서는 간편 연결을 준비 중으로 표시하고 수동 연결을 유지합니다. 서버의 준비 상태를 조회하며 프런트에 네이버 앱 시크릿을 설정하지 않습니다.
로컬 1번 워크스페이스의 소유자는 **내 스토어로 테스트 연결**으로 서버에 저장된 앱의 본인 스토어를 연결할 수 있습니다. 버튼 클릭 후 조회된 채널을 선택·저장하며 앱 정보를 다시 입력하거나 팝업에 로그인할 필요가 없습니다. 이 기능은 서버에서 지정한 워크스페이스에만 허용하며 운영 환경에서는 비활성화됩니다. 나중에 같은 연결을 간편 연결로 전환할 수 있습니다.
간편 연결은 소유자가 팝업 인증 후 스토어·워크스페이스·요금제를 검토하고 확정합니다. 승인 결과가 불확실하면 상태만 재조회하며 승인 POST를 자동 재전송하지 않습니다. 기존 수동 연결의 전환은 해당 행에서 시작하며 같은 판매자의 연결 ID와 채널을 유지합니다. 실제 팝업 인증에는 등록된 HTTPS 동일 출처 프록시와 쿠키·Origin 전달 설정이 필요합니다. [서버 설정 및 SQL 적용 안내](../ad-backend/docs/naver-oauth-setup.md)를 참고하세요.
수동 연결의 `SELF`는 내스토어용이며 `SELLER`는 대상 판매자의 ID 또는 UID도 입력합니다. 일반 네이버 로그인용 자격 증명과 다릅니다. 연결 후 소유자·멤버가 한 번에 최대 100개 스마트스토어 채널을 선택·저장할 수 있습니다.
상세 화면·상태·요청은 각각 `NaverConnectionsPage.tsx`, `useNaverConnections.ts`, `api/naverConnections.ts`에서 관리합니다.
네이버 메뉴(`/workspaces/:workspaceId/connections/naver`)는 저장된 채널이 있으면 `/naver/performance`, 없으면 `/connections/naver/assets`로 이동합니다. 채널 저장 후에도 해당 채널의 성과로 이동하며, 상단 **자산 편집**에서 연결·채널을 관리합니다.
상품 및 판매 성과 화면은 현재 판매 중 상품의 이미지·가격·재고와 결제일 기준 최초 결제금액·현재 잔여 결제금액·주문 수·최초 수량·평균 주문금액·취소/반품 완료 건수를 표시합니다. 한국 시간 기준 최대 31일의 일별 추이와 상위 10개 상품을 조회하며, 상품과 판매 성과의 실패·재시도는 독립적입니다. 취소·반품 전 최초 결제와 조회 시점의 잔여 금액을 구분하고, 미제공 값은 `—`로 표시합니다. 부분 조회 합계는 표시하지 않습니다.
`NaverPerformancePage.tsx`, `NaverPerformanceUI.tsx`, `useNaverStorePerformance.ts`, `api/naverStores.ts`, `types/naverStore.ts`에서 관리하며 계약·집계 범위는 [서버 문서](../ad-backend/docs/naver-store-performance.md)를 참고하세요. 상품·성과에 추가 프런트 환경변수는 필요하지 않습니다.
화면 목록과 UX/UI 변경 및 검증 범위는 [프론트엔드 UX/UI 분석 문서](docs/FRONTEND_UX_REVIEW.md)를 참고하세요.

## 아임웹

아임웹 앱스토어에서 앱을 사이트에 추가하고 동의하면 사이트 정보를 자동으로 받아 OAuth로 연결합니다. 개발 중인 앱은 개발자센터의 **앱 테스트**에서 사이트를 선택합니다. 서비스 로그인 후 소유한 워크스페이스를 선택하고 **아임웹으로 연결**을 누르며, 사이트 코드는 직접 입력하지 않습니다. 기존 사이트의 재인증은 **아임웹으로 다시 연결** 버튼에서 저장된 정보를 사용합니다. 스토어 저장 후에는 판매 중 상품과 주문 생성일 기준 결제액·환불액·결제 주문 수·평균 주문 금액, 일별 성과를 표시합니다. 조회 기간은 한국 시간 기준 최대 31일이며 통화별 스토어를 선택합니다. 워크스페이스 **아임웹 → 자산 편집**으로 연결과 스토어 선택을 별도로 관리합니다.

상품 등록 화면에서 카테고리·가격·재고·이미지·상세 설명을 검토하고 등록합니다. AI 스튜디오의 상세페이지 결과는 스마트스토어·아임웹에 사용할 수 있고, 광고 이미지는 Meta에만 적용합니다. 생성된 상품 ID가 있으면 부분 실패에도 보존하며 중복 생성 버튼을 제공하지 않습니다. 현재 여러 언어 스토어 사이트는 조회만 지원하며 상품 등록은 아임웹 관리자에서 진행합니다.

서버 Client ID·Secret, 앱 서비스 URL, OAuth 콜백, SQL은 [아임웹 설정 안내](../ad-backend/docs/imweb-integration.md)를 참고하세요. 프론트엔드에 앱 시크릿을 설정하지 않습니다. 앱 서비스 진입 경로는 `/settings/integrations/imweb/connect?siteCode=S...`이며 고객의 워크스페이스 목록에서 소유한 공간을 선택합니다.

## 검증과 빌드

```sh
npm run lint
npm run build
npm run preview
```

빌드 결과는 `dist/`에 생성됩니다. `preview`는 로컬 빌드 확인용 서버입니다.
배포 서버에는 SPA 경로가 `index.html`로 연결되도록 fallback 설정을 적용하고 API 접근 경로를 별도로 구성해야 합니다.
브라우저 기반 UI 검증은 모킹한 API로 진행했으며 실제 서버·Meta OAuth·운영 광고 성과·실제 광고 생성·상태/예산 변경·네이버 운영 계정 연결 검증과 구분합니다.

## 관리자와 기술 지원

`http://localhost:3400/admin`에서 기존 서비스의 관리자 권한 계정으로 로그인합니다. 관리자 서버(`admin-api`, 8481)와 일반 서버(`api`, 8480)를 함께 실행해야 고객 화면 지원을 사용할 수 있습니다. 회원 조회·정지·권한·세션 회수, 워크스페이스 조회·이름·소유권·멤버·초대 관리, 연동 재인증 표시, 관리자 작업 이력을 제공합니다.

로컬에서는 `VITE_ADMIN_API_BASE_URL`을 비워 두면 Vite가 `/admin-api`를 `8481`로 전달합니다. 관리자 화면 주소는 `3400/admin/login`이며, `8481`은 API 서버 주소입니다. 기본 관리자 계정은 자동 생성되지 않습니다. [최초 관리자 지정과 상세 로그인 안내](../ad-backend/docs/admin-local-login.md)를 참고하세요.

기술 지원의 기본 흐름은 **고객 신청·약관 동의 → 토스페이먼츠 9,900원 결제 → 어드민 지원 시작 → 완료**입니다. 고객이 신청할 때 접근에 동의하므로 추가 승인이나 수동 입금 확인은 필요하지 않습니다. 기존 관리자가 대신 등록한 요청은 고객 승인·수동 수납 방식으로 유지합니다. 고객은 워크스페이스 메뉴의 **기술 지원**에서 작업을 신청하고 접근 동의를 철회할 수 있습니다. 지원 요청의 소유자·범위·금액은 등록 후 고정되며, 고객 신청의 담당자는 지원을 처음 시작할 때 배정됩니다. 고객 동의 7일 내에 담당 운영자가 회당 최대 15분 접속할 수 있습니다. 조회 전용과 조회·조작 권한을 구분합니다.

관리자 대신 등록에서는 워크스페이스 이름 또는 소유자 이메일로 검색해 공간을 선택합니다. 현재 소유자의 이름·이메일을 조회하고 고객 회원 ID를 자동 설정하므로 ID를 직접 찾을 필요가 없습니다. 워크스페이스 상세에서 등록하면 해당 공간이 자동 선택되며, 회원 상세에서 등록하면 그 회원이 소유한 공간을 먼저 보여 줍니다. 등록 직전 소유자와 이용 상태를 다시 확인하고, 변경되었다면 고객 정보를 갱신해 다시 확인하도록 안내합니다.

기술 지원 등록의 별도 사유 입력은 없습니다. 회원·워크스페이스 관리와 지원 시작·종료·완료, 고객의 지원 승인·철회는 사유를 쓰지 않고 실행할 수 있습니다. 추가 내용이 필요할 때만 **메모 추가(선택)**를 열어 작성하며, 메모가 없으면 서버에서 수행한 작업을 운영 이력으로 자동 기록합니다. 지원 범위·금액 등 실제 업무 정보와 고객의 접근 동의는 기존대로 확인합니다. 이 동작을 사용하려면 선택 메모를 지원하는 `admin-api`와 `api` 변경을 함께 적용해야 합니다.

관리자 인증과 지원 토큰은 각각 별도의 `sessionStorage`에 저장합니다. 고객 로그인 토큰은 덮어쓰지 않으며, 지원 요청은 `X-Support-Token`만 사용하고 실패 시 일반 고객 토큰으로 재시도하지 않습니다. 지원 중 상단 배너에서 남은 시간과 대상 공간을 확인하고 종료할 수 있습니다. 자산 편집 화면은 저장된 연결만 사용하며 새 OAuth 연결은 고객이 진행합니다.

고객 신청은 토스페이먼츠 결제창과 서버 승인·조회·웹훅을 사용합니다. 결제 키가 없으면 신청을 비활성화하며, 결제 취소·환불은 토스 상점관리자에서 처리합니다. [결제 키 설정·신규 마이그레이션·테스트 안내](../ad-backend/docs/customer-support-payments.md)를 먼저 확인하세요. [기존 지원 권한과 운영 절차](../ad-backend/docs/support-operations.md)도 함께 참고할 수 있습니다.

## AI 스튜디오

관리자 사이드바의 **AI 스튜디오**(`/admin/studio`)에서 광고 이미지·상품 상세페이지 샘플과 생성 지침을 등록하고 공개합니다. **카테고리 관리**(`/admin/studio/categories`)에서 카테고리를 먼저 만든 뒤 샘플에서 선택합니다. 이름 변경은 연결된 샘플에 반영되며 사용 중인 카테고리는 삭제할 수 없습니다. 고객은 워크스페이스의 **AI 스튜디오**(`/workspaces/:workspaceId/studio`)에서 카테고리별로 샘플을 선택한 뒤 상품 정보와 선택적 실제 사진으로 OpenAI 생성을 요청합니다. **내 생성 결과**에서 상태·이미지·상세페이지를 확인합니다. 광고 소재(`AD_IMAGE`)는 Meta 광고 계정만, 상세페이지(`DETAIL_PAGE`)는 네이버 스마트스토어만 선택해 등록 폼으로 이동합니다. 등록 화면에서도 결과 유형을 검사하므로 반대 유형은 불러와 적용할 수 없습니다.

샘플 등록은 **카테고리·유형 선택 → 이미지 업로드 → 저장**으로 진행합니다. 업로드 직후 AI 분석으로 이름·스타일 설명·생성 지침을 자동 입력하고, 필요할 때만 **AI 분석 내용 수정**을 펼쳐 편집합니다. 분석이 실패해도 업로드 이미지를 유지하며 기본 내용으로 저장할 수 있습니다. 직접 수정한 내용은 자동 분석으로 덮지 않습니다. 두 서버 모두 기존 `app.ai-creative.api-key`를 사용하며, 환경변수 `OPEN_API_KEY`와 이전 `OPENAI_API_KEY`도 인식합니다.

등록 화면의 **등록 화면에 적용**은 이미지와 저장된 상세페이지를 폼에 불러옵니다. 실제 광고·상품 등록은 기존 검토 절차를 거칩니다. 스마트스토어 상세페이지 이미지는 서버에서 네이버 이미지 주소로 옮겨 만료되는 미리보기 URL이 상품에 남지 않게 합니다. 생성 요청의 자동 재전송과 중복 클릭은 차단하며 결과가 불확실하면 결과 목록에서 먼저 확인하도록 안내합니다.

일반 API의 OpenAI 키, 두 서버의 S3 설정, 신규 SQL 3개 적용이 필요합니다. 기존 AI 스튜디오 SQL 2개를 이미 적용했다면 `20260928_ai_studio_categories.sql`만 추가로 적용합니다. 기존 텍스트 카테고리는 외래키로 이관하고 빈 값은 미분류로 보존합니다. 프론트엔드 환경 변수에 비밀 키를 넣지 않습니다. [서버 설정·API·사용 안내](../ad-backend/docs/ai-studio.md)를 참고하세요. 기술 지원 세션으로는 AI 스튜디오를 사용할 수 없습니다.

### 스마트스토어 주문·배송·환불

네이버 상품 및 판매 성과 화면의 **주문·배송·환불 관리**에서 날짜별 상품 주문, 결제 내역, 배송 상태와 배송지, 취소·반품·교환 내역을 조회합니다. 상품 주문 번호로도 바로 조회할 수 있습니다. 발주 확인·발송·취소 승인·반품 승인은 처리 내용을 확인한 후 적용되며, 반품 승인은 상품 수령 확인이 필요합니다. 승인 접수와 실제 구매자 환불 입금 완료는 구분해 표시합니다.

정산 예정일 기준 내역은 최대 28일씩 페이지 단위로 조회하며 기간 전체 합계로 표시하지 않습니다. 여러 채널의 정산을 구분할 수 없는 연결에서는 정산 조회가 제한됩니다. 설정과 API 지원 범위는 [스마트스토어 주문 관리 안내](../ad-backend/docs/naver-order-management.md)를 참고하세요.
