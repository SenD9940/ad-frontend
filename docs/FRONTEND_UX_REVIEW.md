# United Ad 프론트엔드 UX/UI 분석 및 개편

## 제품 범위

United Ad는 팀별 워크스페이스를 만들고 멤버, Meta 광고 자산, 네이버 스마트스토어를 연결하며 Meta 캠페인과 성과를 조회하는 서비스입니다.
Meta 성과 분석은 지출·노출·전체 클릭·구매 전환 금액과 CTR·CPC·CPM·ROAS를 제공합니다. 지출·노출·클릭은 기간 합계·일평균을 전환할 수 있습니다. 광고 집행·수정과 전환 건수·쇼핑몰 전체 매출·도달 지표는 포함하지 않습니다.
랜딩의 계정·팀원·자산은 기능 설명을 위한 예시 데이터입니다.

## 화면과 사용자 흐름

| 경로 | 화면 | 주요 행동 |
| --- | --- | --- |
| `/` | 랜딩 | 기능 확인, 제품 미리보기 전환, 로그인·가입 또는 워크스페이스 이동 |
| `/login` | 로그인 | 이메일·비밀번호 입력, 비밀번호 표시, 원래 요청한 화면으로 복귀 |
| `/signup` | 회원가입 | 계정·사용자 정보 입력, 주소 검색 또는 직접 입력, 가입 결과 확인 |
| `/workspaces` | 워크스페이스 목록 | 검색, 공간 선택, 새 공간 생성 |
| `/workspaces/new` | 워크스페이스 만들기 | 이름 입력 및 생성 |
| `/workspaces/:workspaceId` | 워크스페이스 진입 | 저장된 광고 계정이 있으면 Meta 성과, 없으면 자산 편집으로 이동 |
| `/workspaces/:workspaceId/connections/meta` | Meta 진입 | 저장된 광고 계정 확인 후 성과·자산 편집으로 자동 이동 |
| `/workspaces/:workspaceId/connections/meta/assets` | Meta 자산 편집 | 계정 연결·재인증, 자산 조회·선택·저장 후 성과로 이동 |
| `/workspaces/:workspaceId/meta/performance` | Meta 광고 성과 | 저장된 광고 계정 선택, 기간별 합계·일평균, 통화별 전체 성과, 캠페인 검색·성과 조회 |
| `/workspaces/:workspaceId/members` | 멤버 관리 | 이메일 초대, 결과 확인, 멤버 조회·내보내기 |
| `/workspaces/:workspaceId/invite` | 멤버 관리 별칭 | 기존 초대 페이지 주소 유지 |
| `/workspaces/:workspaceId/connections` | 연결 화면 진입 | Meta 진입 흐름으로 이동 |
| `/workspaces/:workspaceId/connections/naver` | 네이버 스마트스토어 연결 | 앱 자격 증명 연결·재연결, 스토어 채널 조회·선택·저장 |
| `/workspaces/:workspaceId/connections/{threads,coupang}` | 준비 중 플랫폼 | 제공 상태 확인 및 Meta 연결 이동 |
| `/invite?token=…` | 초대 수락 | 토큰 검증, 참여 요청, 결과 확인 |
| `/settings/integrations/meta/callback` | Meta 인증 결과 | 성공 시 자산 편집 이동, 실패 시 복구 경로 제공 |
| 그 외 경로 | 찾을 수 없는 페이지 | 홈 또는 워크스페이스로 복귀 |

워크스페이스·초대·인증 결과 화면은 로그인이 필요합니다.

## 권한과 플랫폼 연결

Meta 계정 연결과 재인증은 워크스페이스 소유자가 수행합니다.
참여 멤버는 연결된 계정과 자산을 조회하고 선택·저장할 수 있습니다.
광고 계정, Facebook 페이지, 연결된 Instagram 프로필을 구분하며 자산 선택 상한은 기존과 동일하게 유지합니다.
멤버 초대는 이메일 추가·발송 결과 확인 흐름을 제공합니다. 멤버 내보내기는 소유자에게만 표시하고, 소유자 본인은 대상에서 제외합니다.
이 UI의 권한 안내와 별개로 실제 요청 권한은 서버에서 검증해야 합니다.
네이버 스마트스토어 연결·재연결은 소유자가 커머스 API의 앱 ID·시크릿으로 수행합니다. 일반 네이버 로그인용 자격 증명은 사용하지 않습니다.
`SELF`는 내스토어용이며 판매자 ID를 보내지 않습니다. `SELLER`는 권한을 가진 앱과 대상 판매자 ID 또는 UID(`account_id`)가 필요합니다.
브라우저 OAuth 콜백 없이 서버가 자격 증명으로 인증합니다. 시크릿·토큰 원문은 응답에 포함하지 않습니다.
연결 후 소유자와 참여 멤버는 스마트스토어 채널을 조회하고 한 번에 최대 100개를 저장할 수 있습니다. 이미 저장한 다른 채널은 유지됩니다.
지원 채널은 스마트스토어(`STOREFARM`)이며 검색광고·쇼핑윈도·상품·주문 처리는 포함하지 않습니다. Threads·Coupang은 준비 중으로 표시합니다.

## Meta 성과 조회 기준

- 소유자·참여 멤버 모두 저장된 Meta/Facebook 광고 계정의 캠페인과 성과를 조회합니다. `assetId`에는 `connections[].assets[].id`를 사용하며 연결 ID나 `act_*`를 보내지 않습니다.
- 저장된 광고 계정이 있으면 Meta 기본 화면은 성과를 자동 조회합니다. 성과 화면의 자산 편집 버튼으로 선택·연결 화면을 열 수 있습니다. 저장과 목록 재조회가 모두 성공하고 광고 계정이 존재하면 성과 화면으로 돌아오며, 실패하거나 페이지·프로필만 저장한 경우에는 편집 화면에 머뭅니다.
- 전체 선택은 `/meta/insights`, 개별 계정은 `/meta/ad-accounts/{assetId}/campaigns`와 `/insights`에 연결합니다. 같은 외부 광고 계정의 중복 제거와 통화별 집계는 서버 결과를 따릅니다.
- `?assetId=내부ID`로 저장된 광고 계정에서 바로 이동합니다. 저장되지 않은 ID는 조회하지 않고 다시 선택하도록 안내합니다.
- 날짜는 시작일·종료일을 포함해 최대 366일입니다. 입력 중인 기간과 조회에 적용된 기간을 구분하며, 날짜만 변경하면 날짜와 무관한 캠페인 목록은 재조회하지 않습니다.
- 전체 요약과 계정 표는 선택한 통화만 표시합니다. 지출·노출·클릭의 일평균은 성과가 없는 날을 포함한 전체 기간 기준이며, CTR·CPC·CPM·ROAS는 합계 기반의 서버 값을 유지합니다. 각 계정의 현지 시간대를 표시합니다.
- `metrics.purchase_value`는 구매 전환 금액, `metrics.roas`는 배수로 표시합니다. 전체·계정·캠페인 모두 서버 값을 사용하며 ROAS를 직접 평균하거나 일수로 나누지 않습니다. `daily_average`에는 구매 전환 금액이 없으므로 일평균 모드에서도 해당 금액은 기간 합계로 표시합니다.
- ROAS는 구매 전환 금액 ÷ 지출입니다. 지출이 0이면 `null`을 대시로, 지출은 있지만 보고된 구매 전환 금액이 0이면 `0배`로 구분합니다. Meta의 기여 설정·추적에 따른 구매 전환 가치로서 쇼핑몰 전체 매출과 다르며, 0이 실제 구매 부재를 확정하지 않음을 안내합니다. 누락되거나 잘못된 응답 필드를 임의로 0으로 바꾸지 않습니다.
- 캠페인 목록과 기간 성과를 ID로 병합합니다. 성과가 없는 캠페인과 메타데이터가 없는 성과 행도 유지합니다. 별도 조회된 계정 합계가 캠페인 행의 합과 다를 수 있음을 안내합니다.
- 0과 계산 불가(null), 성과 없음, 요청 실패를 구분합니다. 전체 요청 실패 시 일부 계정만으로 합계를 만들지 않습니다. 캠페인·성과 중 하나만 실패하면 성공한 정보를 유지하며 각 요청을 다시 시도할 수 있습니다.
- 계정·기간 변경 시 이전 요청을 취소하고 이전 결과를 즉시 숨겨 늦게 도착한 응답이 새 선택에 표시되지 않도록 합니다.

## 검증 범위와 남은 확인

- 정적 검사·프로덕션 빌드 명령: `npm run lint`, `npm run build`.
- 실제 Chrome에서 1440px·390px·320px 너비의 랜딩·인증·작업 화면을 확인했습니다.
- 랜딩 메뉴·CTA·미리보기 전환, 모바일 가로 넘침과 런타임 오류를 확인했습니다.
- 작업 화면은 브라우저에서 API 응답을 모킹해 목록·폼·자산 선택과 저장·초대·내보내기 동작 및 요청 내용을 확인했습니다.
- 로딩·빈 상태·API 오류·소유자/멤버 권한·재인증 필요 상태를 포함합니다.
- Meta 성과는 모킹한 API로 12개 시나리오를 확인했습니다. 통화별 합계·서버 일평균·null/0, 캠페인 병합, 366일 경계, 독립 요청 실패, 계정 A→B→A·기간 전환 중 응답 경합을 포함합니다. 저장된 광고 계정 링크가 내부 자산 ID로 올바른 API를 호출하는 것도 확인했습니다.
- 기본 진입·자산 편집 분리 후 8개 흐름을 추가 확인했습니다. 저장 자산 유무에 따른 자동 이동, 편집·저장 후 새 계정 성과 조회, 저장 실패·페이지/프로필만 저장 시 편집 유지, 목록 오류 재시도, OAuth 편집 복귀와 모바일 메뉴 활성·가로 넘침을 포함합니다.
- ROAS 확장 후 7개 시나리오를 확인했습니다. 통화별 합계 기반 ROAS, 구매 전환 금액 표시, 일평균 전환 시 기간 값 유지, null/0/성과 없음 구분, 소수점 정밀도 안내, 누락·문자열·음수 응답 거부를 포함합니다.
- 브라우저 검증 도구는 임시 경로에서 실행했으며 프로젝트 의존성에 추가하지 않았습니다. 프로젝트에 상시 실행되는 E2E 테스트 묶음을 추가한 것은 아닙니다.
- 실제 서버와의 통합, 실제 Meta OAuth 왕복 인증·운영 광고 성과, 네이버 운영 계정 연결, 실제 초대 메일 전달은 이번 UI 검증에서 확인하지 않았습니다.
