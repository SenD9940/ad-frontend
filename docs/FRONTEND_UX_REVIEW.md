# United Ad 프론트엔드 UX/UI 분석 및 개편

## 제품 범위

United Ad는 팀별 워크스페이스를 만들고 멤버, Meta 광고 자산, 네이버 스마트스토어를 연결하며 Meta 캠페인과 성과를 조회하는 서비스입니다.
네이버는 저장된 채널의 판매 중 상품과 결제일 기준 판매 성과를 제공합니다. 최초 결제금액·수량과 취소·반품 반영 잔여 결제금액을 구분하며, 정산금·광고 ROAS는 포함하지 않습니다.
Meta 성과 분석은 지출·노출·전체 클릭·구매 전환 금액과 CTR·CPC·CPM·ROAS를 제공합니다. 지출·노출·클릭은 기간 합계·일평균을 전환할 수 있습니다. 트래픽·판매 목표의 이미지 광고를 일시정지 상태로 등록하고, 광고·광고세트·캠페인의 이름·상태와 기존 일 예산을 수정할 수 있습니다. 전환 건수·쇼핑몰 전체 매출·도달 지표는 포함하지 않습니다.
랜딩의 계정·팀원·자산은 기능 설명을 위한 예시 데이터입니다.

## 권한과 플랫폼 연결

Meta 계정 연결과 재인증은 워크스페이스 소유자가 수행합니다.
참여 멤버는 연결된 계정과 자산을 조회하고 선택·저장할 수 있습니다.
광고 계정, Facebook 페이지, 연결된 Instagram 프로필을 구분하며 자산 선택 상한은 기존과 동일하게 유지합니다.
멤버 초대는 이메일 추가·발송 결과 확인 흐름을 제공합니다. 멤버 내보내기는 소유자에게만 표시하고, 소유자 본인은 대상에서 제외합니다.
이 UI의 권한 안내와 별개로 실제 요청 권한은 서버에서 검증해야 합니다.
네이버 스마트스토어 연결·재연결은 소유자가 커머스 API의 앱 ID·시크릿으로 수행합니다. 일반 네이버 로그인용 자격 증명은 사용하지 않습니다.
`SELF`는 내스토어용이며 판매자 ID를 보내지 않습니다. `SELLER`는 권한을 가진 앱과 대상 판매자 ID 또는 UID(`account_id`)가 필요합니다.
브라우저 OAuth 콜백 없이 서버가 자격 증명으로 인증합니다. 시크릿·토큰 원문은 응답에 포함하지 않습니다.
연결 후 소유자와 참여 멤버는 스마트스토어 채널을 조회하고 한 번에 최대 100개를 저장할 수 있습니다. 이미 저장한 다른 채널은 유지됩니다.
지원 채널은 스마트스토어(`STOREFARM`)이며 검색광고·쇼핑윈도·상품·주문 처리는 포함하지 않습니다. Threads·Coupang은 준비 중으로 표시합니다.

## Meta 성과 조회 기준

- 소유자·참여 멤버 모두 저장된 Meta/Facebook 광고 계정의 캠페인과 성과를 조회합니다. `assetId`에는 `connections[].assets[].id`를 사용하며 연결 ID나 `act_*`를 보내지 않습니다.
- 저장된 광고 계정이 있으면 Meta 기본 화면은 성과를 자동 조회합니다. 성과 화면의 자산 편집 버튼으로 선택·연결 화면을 열 수 있습니다. 저장과 목록 재조회가 모두 성공하고 광고 계정이 존재하면 성과 화면으로 돌아오며, 실패하거나 페이지·프로필만 저장한 경우에는 편집 화면에 머뭅니다.
- 전체 선택은 `/meta/insights`, 개별 계정은 `/meta/ad-accounts/{assetId}/campaigns`와 `/insights`에 연결합니다. 같은 외부 광고 계정의 중복 제거와 통화별 집계는 서버 결과를 따릅니다.
- `?assetId=내부ID`로 저장된 광고 계정에서 바로 이동합니다. 저장되지 않은 ID는 조회하지 않고 다시 선택하도록 안내합니다.
- 날짜는 시작일·종료일을 포함해 최대 366일입니다. 입력 중인 기간과 조회에 적용된 기간을 구분하며, 날짜만 변경하면 날짜와 무관한 캠페인 목록은 재조회하지 않습니다.
- 전체 요약과 계정 표는 선택한 통화만 표시합니다. 지출·노출·클릭의 일평균은 성과가 없는 날을 포함한 전체 기간 기준이며, CTR·CPC·CPM·ROAS는 합계 기반의 서버 값을 유지합니다. 각 계정의 현지 시간대를 표시합니다.
- `metrics.purchase_value`는 구매 전환 금액, `metrics.roas`는 배수로 표시합니다. 전체·계정·캠페인 모두 서버 값을 사용하며 ROAS를 직접 평균하거나 일수로 나누지 않습니다. `daily_average`에는 구매 전환 금액이 없으므로 일평균 모드에서도 해당 금액은 기간 합계로 표시합니다.
- ROAS는 구매 전환 금액 ÷ 지출입니다. 지출이 0이면 `null`을 대시로, 지출은 있지만 보고된 구매 전환 금액이 0이면 `0배`로 구분합니다. Meta의 기여 설정·추적에 따른 구매 전환 가치로서 쇼핑몰 전체 매출과 다르며, 0이 실제 구매 부재를 확정하지 않음을 안내합니다. 누락되거나 잘못된 응답 필드를 임의로 0으로 바꾸지 않습니다.
- 캠페인 목록과 기간 성과를 ID로 병합합니다. 성과가 없는 캠페인과 메타데이터가 없는 성과 행도 유지합니다. 별도 조회된 계정 합계가 캠페인 행의 합과 다를 수 있음을 안내합니다.
- 0과 계산 불가(null), 성과 없음, 요청 실패를 구분합니다. 전체 요청 실패 시 일부 계정만으로 합계를 만들지 않습니다. 캠페인·성과 중 하나만 실패하면 성공한 정보를 유지하며 각 요청을 다시 시도할 수 있습니다.
- 계정·기간 변경 시 이전 요청을 취소하고 이전 결과를 즉시 숨겨 늦게 도착한 응답이 새 선택에 표시되지 않도록 합니다.

## Meta 광고 등록 기준

- 성과 화면의 광고 등록 버튼에서 진입합니다. 선택 중인 광고 계정은 내부 자산 ID로 전달합니다. 전체 성과에서 진입하면 등록 계정을 명시적으로 선택합니다.
- 광고 계정·페이지·Instagram 프로필은 동일한 Meta 연결에서만 선택합니다. 페이지를 변경하면 Instagram 선택을 초기화하고 해당 페이지에 연결된 저장 프로필만 제공합니다.
- `useMetaAdPages.ts`는 계정 선택마다 `GET /meta/ad-accounts/{assetId}/pages`로 해당 계정의 `promote_pages`를 조회합니다. `MetaPageSetup.tsx`에는 저장 여부와 무관하게 현재 사용할 수 있는 페이지만 표시합니다. 기존 저장 페이지는 선택 즉시 사용하고, 새 페이지는 같은 경로의 POST `{external_id}`로 저장한 뒤 내부 ID를 등록 폼에 반영합니다. 저장 응답에는 기존 광고 계정도 유지됩니다. 계정 변경·재조회 시 이전 선택과 늦은 응답을 무효화하고, 페이지 없음·조회 실패·저장 실패를 구분합니다.
- 트래픽은 픽셀을 보내지 않으며 판매는 숫자 픽셀 ID를 필수로 받습니다. HTTPS URL, 이름·본문 길이, 국가코드, 연령, 예산 정수를 검증합니다. 예산은 계정 통화의 최소 단위이며 금액·환율을 변환하지 않습니다.
- 이미지는 파일 업로드를 기본으로 제공하며 외부 URL 입력으로 전환할 수 있습니다. 파일은 JPEG/PNG·10MiB·각 변 10,000px/총 2,500만 픽셀을 검증하고 계정별 `/images`에 `file`로 전송합니다. 진행 중에는 검토를 막고, 실패 시 수동 재시도·선택 해제를 제공합니다. 업로드 요청은 401 자동 재전송을 사용하지 않습니다.
- 업로드 성공 응답의 `image_key` 또는 외부 `image_url` 중 하나만 광고 요청에 포함합니다. 미리보기는 로컬 파일 URL을 생성·해제해 서명 URL 만료에 영향을 받지 않도록 합니다. 검토 후 복귀해도 선택 파일을 유지하며, 광고 계정 변경 시 선택과 늦은 응답을 무효화합니다. 화면에서 이미지 선택을 해제해도 서버 파일을 삭제하지 않습니다.
- 입력 단계에서 요청하지 않고 등록 내용 확인 후 `POST /meta/ad-accounts/{assetId}/ads`를 한 번 호출합니다. 캠페인·광고세트·광고는 모두 일시정지 상태입니다. 소유자·참여 멤버가 사용할 수 있으나 기존 Meta 토큰에 `ads_management` 권한이 필요합니다.
- HTTP 실패 응답에서도 생성된 ID·실패 단계를 보존합니다. 부분 생성·결과 불명 상태에서는 Meta 광고 관리자에서 결과를 확인한 뒤 새 등록을 준비할 수 있습니다. 자동 재시도·자동 삭제·활성화는 수행하지 않습니다.

## Meta 광고 수정 기준

- 성과 화면의 광고 수정 버튼은 선택한 계정을 유지합니다. 개별 계정의 캠페인 행과 광고 생성 완료 화면의 광고·광고세트·캠페인 링크는 내부 `assetId`, 대상 `type`, 외부 `objectId`를 전달합니다. 그 외 대상은 Meta 광고 관리자에 표시된 숫자 ID를 입력합니다.
- 저장된 광고 계정만 선택하며 재인증이 필요한 계정의 제출을 막습니다. 실제 워크스페이스 멤버·토큰의 `ads_management` 권한과 대상 계정 소속은 서버에서 검증합니다. 계정이나 유형을 변경하면 이전 대상 ID와 변경 필드를 초기화합니다.
- 선택한 항목만 검토하고 `/meta/ad-accounts/{assetId}/ads/{adId}`, `/ad-sets/{adSetId}`, `/campaigns/{campaignId}` 중 하나에 PATCH합니다. 이름은 공백이 아닌 최대 255자, 상태는 `ACTIVE`·`PAUSED`, 일 예산은 JavaScript에서 정확하게 표현할 수 있는 양의 정수만 허용합니다. 전송 시 `daily_budget`을 사용하고 미선택·null 필드는 생략합니다.
- 광고에는 예산 입력을 제공하지 않습니다. 광고세트의 예산 공유, 캠페인 예산 관리 시 광고세트 예산 변경 거부, 기존 일 예산만 수정 가능하다는 범위를 입력·검토 화면에 안내합니다. 서버가 현재 예산 방식을 확인하며 총 예산이나 예산 관리 단계의 전환은 지원하지 않습니다.
- 현재 계약에 광고·광고세트 상세 조회가 없으므로 저장 전 값을 추정해서 표시하지 않습니다. 새 값을 명시적으로 선택하며 상태의 기본값도 비워 둡니다. 활성화의 광고비 발생 가능성, 상위 상태와 하위 광고에 미치는 영향을 검토 단계에서 안내합니다.
- 검토 전에는 요청하지 않습니다. 적용 중 연속 클릭을 막고 401 갱신에 따른 요청 재전송·자동 재시도·관련 대상 자동 활성화를 하지 않습니다. `success: true`와 대상 ID가 일치하는 응답만 성공으로 처리하고 실제 게재 완료와 구분합니다.
- HTTP 408·5xx·네트워크 오류·잘못된 성공 응답은 결과 불명으로 처리합니다. 요청한 값을 보존하고 Meta 광고 관리자에서 변경 결과를 확인했다고 표시한 뒤 입력으로 돌아갈 수 있습니다. 명확한 거절도 사용자가 입력·검토 단계를 다시 거친 뒤 요청합니다.

## 검증 범위와 남은 확인

- 정적 검사·프로덕션 빌드 명령: `npm run lint`, `npm run build`.
- 실제 Chrome에서 1440px·390px·320px 너비의 랜딩·인증·작업 화면을 확인했습니다.
- 랜딩 메뉴·CTA·미리보기 전환, 모바일 가로 넘침과 런타임 오류를 확인했습니다.
- 작업 화면은 브라우저에서 API 응답을 모킹해 목록·폼·자산 선택과 저장·초대·내보내기 동작 및 요청 내용을 확인했습니다.
- 로딩·빈 상태·API 오류·소유자/멤버 권한·재인증 필요 상태를 포함합니다.
- Meta 성과는 모킹한 API로 12개 시나리오를 확인했습니다. 통화별 합계·서버 일평균·null/0, 캠페인 병합, 366일 경계, 독립 요청 실패, 계정 A→B→A·기간 전환 중 응답 경합을 포함합니다. 저장된 광고 계정 링크가 내부 자산 ID로 올바른 API를 호출하는 것도 확인했습니다.
- 기본 진입·자산 편집 분리 후 8개 흐름을 추가 확인했습니다. 저장 자산 유무에 따른 자동 이동, 편집·저장 후 새 계정 성과 조회, 저장 실패·페이지/프로필만 저장 시 편집 유지, 목록 오류 재시도, OAuth 편집 복귀와 모바일 메뉴 활성·가로 넘침을 포함합니다.
- ROAS 확장 후 7개 시나리오를 확인했습니다. 통화별 합계 기반 ROAS, 구매 전환 금액 표시, 일평균 전환 시 기간 값 유지, null/0/성과 없음 구분, 소수점 정밀도 안내, 누락·문자열·음수 응답 거부를 포함합니다.
- 광고 등록은 14개 모의 API 시나리오로 내부 자산 ID·입력 값 전달, 트래픽/판매 요청, 같은 연결의 페이지·프로필 제한, 잘못된 입력 차단, 연속 클릭 1회 요청, 부분 생성·결과 불명 ID 보존, 401 자동 재전송 차단과 모바일 화면을 확인했습니다. 실제 광고 생성 요청은 보내지 않았습니다.
- 페이지 미저장 복구는 7개 모의 API 시나리오로 페이지 선택·저장 후 등록 폼 진입, 기존 광고 계정 유지, 내부 페이지 ID 선택, 조회 결과 없음·조회/저장 실패 재시도, 늦은 다른 연결 응답 무시, 잘못된 저장 응답 차단, 재인증 상태를 확인했습니다. 1440px·390px·320px에서 가로 넘침도 확인했습니다.
- 광고 계정별 페이지 조회로 전환한 뒤 13개 모의 API 시나리오를 확인했습니다. 같은 연결의 계정별 페이지 분리, 저장 페이지 재사용·새 페이지 1회 저장, 내부 페이지 ID 광고 요청, 검토 후 복귀·프로필 초기화, 빈 목록·오류·재조회, 늦은 조회/저장 응답과 계정 왕복·동시 저장을 포함합니다. 1440px·390px·320px에서 선택·입력·검토 화면의 가로 넘침도 확인했습니다.
- S3 이미지 연동은 20개 브라우저 모의 API 시나리오로 multipart 파일·인증·진행률, 업로드 중 검토 차단, 미리보기와 검토 후 복귀, `image_key`/`image_url` 단일 전달, 잘못된 파일·용량·크기 차단, 오류·수동 재시도·401 재전송 방지, 이미지 교체·선택 해제, 계정 변경·이전 응답 차단을 확인했습니다. 키 접두사가 없는 설정과 다른 계정의 잘못된 응답도 검증했으며 1440px·390px·320px에서 업로드·검토 화면의 가로 넘침이 없었습니다. 실제 AWS 업로드·Meta 광고 생성은 수행하지 않았습니다.
- 광고 수정 API 모듈은 37개 모의 검증으로 세 대상 경로, 선택 필드·null 생략, 입력 검증, 단일 요청과 불확실한 응답 처리를 확인했습니다. 백엔드의 수정 API·비즈니스·Meta 클라이언트 테스트 91개도 통과했습니다. 실행 중인 로컬 백엔드의 OpenAPI에서 세 PATCH 경로가 노출되는 것을 확인했습니다.
- 광고 수정 화면은 20개 브라우저 모의 시나리오로 필드별 PATCH, 입력 범위, 중복 클릭 차단, 계정·유형·주소 변경 시 초기화, 400·403·401 수동 재확인과 자동 재전송 방지, 결과 불명 확인 절차, 재인증·빈 계정 안내, 성과 표와 광고 생성 완료 화면의 수정 링크를 확인했습니다. 1440px·390px·320px에서 입력·확인·성공 화면의 가로 넘침도 확인했습니다. 실제 Meta 광고 상태나 예산을 변경하지 않았습니다.
- 브라우저 검증 도구는 임시 경로에서 실행했으며 프로젝트 의존성에 추가하지 않았습니다. 프로젝트에 상시 실행되는 E2E 테스트 묶음을 추가한 것은 아닙니다.
- 실제 서버와의 통합, 실제 Meta OAuth 왕복 인증·운영 광고 성과·광고 생성·상태/예산 변경, 네이버 운영 계정 연결, 실제 초대 메일 전달은 이번 UI 검증에서 확인하지 않았습니다.
- 실제 운영 환경에서는 API 주소·CORS·쿠키·Meta OAuth 콜백과 네이버 앱의 서버 허용 IP·판매자 권한 설정을 맞춘 뒤 계정 연결부터 자산 저장까지 다시 확인해야 합니다.
