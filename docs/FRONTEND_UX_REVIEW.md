# United Ad 프론트엔드 UX/UI 분석 및 개편

## 제품 범위

United Ad는 팀별 워크스페이스를 만들고 멤버, Meta 광고 자산, 네이버 스마트스토어를 연결하는 서비스입니다.
현재 화면과 API가 제공하는 기능을 기준으로 구성했으며, 광고 집행·성과 분석 기능은 포함하지 않습니다.
랜딩의 계정·팀원·자산은 기능 설명을 위한 예시 데이터입니다.

## 화면과 사용자 흐름

| 경로 | 화면 | 주요 행동 |
| --- | --- | --- |
| `/` | 랜딩 | 기능 확인, 제품 미리보기 전환, 로그인·가입 또는 워크스페이스 이동 |
| `/login` | 로그인 | 이메일·비밀번호 입력, 비밀번호 표시, 원래 요청한 화면으로 복귀 |
| `/signup` | 회원가입 | 계정·사용자 정보 입력, 주소 검색 또는 직접 입력, 가입 결과 확인 |
| `/workspaces` | 워크스페이스 목록 | 검색, 공간 선택, 새 공간 생성 |
| `/workspaces/new` | 워크스페이스 만들기 | 이름 입력 및 생성 |
| `/workspaces/:workspaceId` | 워크스페이스 진입 | Meta 연결 화면으로 이동 |
| `/workspaces/:workspaceId/connections/meta` | Meta 연결 | 계정 연결·재인증, 자산 조회·선택·저장 |
| `/workspaces/:workspaceId/members` | 멤버 관리 | 이메일 초대, 결과 확인, 멤버 조회·내보내기 |
| `/workspaces/:workspaceId/invite` | 멤버 관리 별칭 | 기존 초대 페이지 주소 유지 |
| `/workspaces/:workspaceId/connections` | 연결 화면 진입 | Meta 연결 화면으로 이동 |
| `/workspaces/:workspaceId/connections/naver` | 네이버 스마트스토어 연결 | 앱 자격 증명 연결·재연결, 스토어 채널 조회·선택·저장 |
| `/workspaces/:workspaceId/connections/{threads,coupang}` | 준비 중 플랫폼 | 제공 상태 확인 및 Meta 연결 이동 |
| `/invite?token=…` | 초대 수락 | 토큰 검증, 참여 요청, 결과 확인 |
| `/settings/integrations/meta/callback` | Meta 인증 결과 | 성공 시 자산 선택 이동, 실패 시 복구 경로 제공 |
| 그 외 경로 | 찾을 수 없는 페이지 | 홈 또는 워크스페이스로 복귀 |

워크스페이스·초대·인증 결과 화면은 로그인이 필요합니다.

## 기존 문제와 변경

| 확인한 문제 | 변경 내용 |
| --- | --- |
| 랜딩이 비어 있어 서비스 목적과 시작 경로가 드러나지 않음 | 실제 기능 기반 소개, 전환 가능한 미리보기, 시작 단계와 CTA 추가 |
| 공개 페이지와 작업 화면의 탐색 구조가 유사함 | 공개 레이아웃과 사이드바 기반 작업 레이아웃 분리 |
| 폼·상세 화면의 간격과 정보 위계가 일관되지 않음 | 공통 색상·타이포·입력 스타일, 인증 및 상세 공통 UI 적용 |
| 연결·선택·저장 과정에서 상태 파악이 어려움 | 연결 상태, 자산 유형, 선택 상태, 저장 결과와 재인증 안내 구분 |
| 빈 목록·오류·잘못된 경로에서 다음 행동이 불명확함 | 상태별 안내와 다시 시도·돌아가기·생성 버튼 제공 |
| 모바일에서 데스크톱 구조를 그대로 보기 어려움 | 좁은 화면용 메뉴, 카드·폼 재배치, 가로 넘침 확인 |
| effect의 동기 상태 초기화와 인증 모듈 혼합 export로 lint 오류 발생 | 초기 상태·파생값 정리, 컨텍스트와 Provider 분리 |

헤더·푸터의 기존 사업자 정보와 사용자 변경 사항은 보존했습니다.

## 코드 구조

- `src/main.tsx`, `src/styles/`: 테마와 전역 스타일을 한 번 적용합니다. 보라색 주 색상, 밝은 배경, 공통 테두리·포커스·모션 축소 설정을 사용합니다.
- `src/components/layout/MainLayout.tsx`: 공개 화면의 헤더·본문·푸터를 담당합니다.
- `src/components/layout/AppShell.tsx`: 작업 화면의 메뉴와 공통 탐색을 담당합니다.
- `WorkspaceHomeLayout.tsx`, `WorkspaceAppLayout.tsx`: 전체 공간 목록과 선택한 공간의 레이아웃을 구분합니다. 공간 ID가 바뀌면 하위 화면을 다시 마운트해 상태를 초기화합니다.
- `src/components/common/RouteEffects.tsx`: 경로별 문서 제목과 페이지 이동 시 스크롤을 관리합니다.
- `src/components/auth/`, `src/pages/workspace/WorkspaceDetailUI.tsx`: 인증 및 상세 화면의 재사용 UI를 제공합니다.
- `src/auth/AuthContext.ts`, `AuthProvider.tsx`, `session.ts`: 로그인 상태·토큰 저장·구독을 담당합니다.
- `src/hooks/`: 폼 검증, 요청 진행 상태, 권한 판단, 사용자 행동을 화면과 분리합니다.
- `src/api/`: Axios 요청, 응답 형식 변환, 토큰 갱신, 오류 메시지 처리를 담당합니다. 기존 API 계약을 유지합니다.
- `src/pages/workspace/NaverConnectionsPage.tsx`, `src/hooks/useNaverConnections.ts`, `src/api/naverConnections.ts`: 스마트스토어 연결 UI, 자격 증명·채널 상태, 네이버 연결 API 요청을 분리합니다.
- `src/types/`: 사용자·워크스페이스·플랫폼·자산의 타입을 정의합니다.

## 권한과 플랫폼 연결

Meta 계정 연결과 재인증은 워크스페이스 소유자가 수행합니다.
참여 멤버는 연결된 계정과 자산을 조회하고 선택·저장할 수 있습니다.
광고 계정, Facebook 페이지, 연결된 Instagram 프로필을 구분하며 자산 선택 상한은 기존과 동일하게 유지합니다.
멤버 초대는 이메일 추가·발송 결과 확인 흐름을 제공합니다. 멤버 내보내기는 소유자에게만 표시하고, 소유자 본인은 대상에서 제외합니다.
이 UI의 권한 안내와 별개로 실제 요청 권한은 서버에서 검증해야 합니다.
네이버 스마트스토어 연결·재연결은 소유자가 커머스 API의 앱 ID·시크릿으로 수행합니다. 일반 네이버 로그인용 자격 증명은 사용하지 않습니다.
`SELF`는 내스토어용이며 판매자 ID를 보내지 않습니다. `SELLER`는 권한을 가진 앱과 대상 판매자 ID 또는 UID(`account_id`)가 필요합니다.
브라우저 OAuth 콜백 없이 서버가 자격 증명으로 인증합니다. 시크릿·토큰 원문은 응답에 포함하지 않습니다.
연결 후 소유자와 참여 멤버는 스마트스토어 채널을 조회하고 한 번에 최대 100개를 저장할 수 있습니다. 이미 저장한 다른 채널은 유지됩니다.
지원 채널은 스마트스토어(`STOREFARM`)이며 검색광고·쇼핑윈도·상품·주문 처리는 포함하지 않습니다. Threads·Coupang은 준비 중으로 표시합니다.

## 검증 범위와 남은 확인

- 정적 검사·프로덕션 빌드 명령: `npm run lint`, `npm run build`.
- 실제 Chrome에서 1440px·390px·320px 너비의 랜딩·인증·작업 화면을 확인했습니다.
- 랜딩 메뉴·CTA·미리보기 전환, 모바일 가로 넘침과 런타임 오류를 확인했습니다.
- 작업 화면은 브라우저에서 API 응답을 모킹해 목록·폼·자산 선택과 저장·초대·내보내기 동작 및 요청 내용을 확인했습니다.
- 로딩·빈 상태·API 오류·소유자/멤버 권한·재인증 필요 상태를 포함합니다.
- 브라우저 검증 도구는 임시 경로에서 실행했으며 프로젝트 의존성에 추가하지 않았습니다. 프로젝트에 상시 실행되는 E2E 테스트 묶음을 추가한 것은 아닙니다.
- 실제 서버와의 통합, 실제 Meta OAuth 왕복 인증, 네이버 운영 계정 연결, 실제 초대 메일 전달은 이번 UI 검증에서 확인하지 않았습니다.
- 실제 운영 환경에서는 API 주소·CORS·쿠키·Meta OAuth 콜백과 네이버 앱의 서버 허용 IP·판매자 권한 설정을 맞춘 뒤 계정 연결부터 자산 저장까지 다시 확인해야 합니다.
