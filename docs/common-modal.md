# 공통 모달

사용자 화면과 어드민은 `App.tsx`의 `ModalProvider`를 공유합니다. 오류·안내·완료 메시지와 간단한 확인은 `useModal()`을 사용합니다.

```tsx
const modal = useModal()

void modal.info({ title: '이용 안내', message: '화면 사용 방법입니다.' })
void modal.error({ title: '저장 실패', message: '저장하지 못했습니다. 입력 내용을 확인해 주세요.' })
void modal.success({ message: '변경 내용을 저장했습니다.' })

const accepted = await modal.confirm({
  title: '선택을 해제하시겠어요?',
  message: '편집 중인 선택 내용을 비웁니다.',
  confirmLabel: '선택 해제',
  cancelLabel: '유지',
  danger: true,
})
if (!accepted) return
// 사용자가 확인한 작업만 실행
```

모든 메시지 메서드는 `Promise<boolean>`을 반환합니다. 확인 버튼은 `true`, 취소·닫기·Esc·화면 이탈은 `false`로 완료합니다. 완료 메시지 다음에 이동하려면 `if (await modal.success(...))`처럼 확인 결과를 검사하세요. 이미 완료된 저장을 다시 호출하지 않도록 결과 화면도 유지해야 합니다.

모달 요청은 순서대로 표시됩니다. 동시에 대기하는 동일 문자열의 오류는 한 번의 확인으로 닫힙니다. 화면을 이동하거나 요청한 컴포넌트가 사라지면 해당 요청도 취소되며, 이전 화면에서 늦게 도착한 오류는 표시하지 않습니다. 이벤트 핸들러에서 호출하고 렌더링 중 호출하지 마세요. 메시지는 일반 React 텍스트/요소로 렌더링하며 HTML 문자열을 삽입하지 않습니다.

조회 훅처럼 오류 상태를 관리하는 곳은 `useErrorModal(error, '조회 실패')`을 사용할 수 있습니다. 같은 오류가 유지되는 동안에는 다시 열리지 않으며, 재조회로 오류가 해제되면 닫히고 다음 실패는 다시 표시됩니다. 컴포넌트가 사라지면 그 훅이 띄운 메시지도 정리합니다. 공유 조회 훅에서 이미 표시한 오류를 소비 페이지에서 다시 표시하지 마세요. 로컬 필드 검증과 서버 오류가 같은 상태를 쓰면 서버 오류 상태를 분리해야 합니다.

입력 폼이나 요청 완료까지 닫기를 막아야 하는 작업은 제어형 `Modal`을 사용합니다. `confirm()`은 선택만 반환하므로 비동기 저장 창 용도로 사용하지 않습니다.

```tsx
<Modal
  open={reviewOpen}
  title="변경 내용 확인"
  variant="confirm"
  size="lg"
  busy={saving}
  onClose={closeReview}
  footer={<div>{/* 취소 및 적용 버튼 */}</div>}
>
  {/* 검토할 대상, 변경 내용 또는 입력 폼 */}
</Modal>
```

- 네이티브 `dialog`와 portal로 배경 조작을 차단하고 제목에 초기 포커스를 둡니다. 닫을 때 시작 버튼으로 포커스를 복원합니다. 배경 클릭으로는 닫히지 않습니다.
- `busy` 중 닫기와 Esc를 막습니다. 호출 화면도 제출 버튼 비활성화와 동기 ref 잠금으로 중복 요청을 방지해야 합니다. 모달 자체는 API를 호출하거나 재시도하지 않습니다.
- 비동기 작업에서 버튼이 비활성화되어 포커스를 잃었다면 `returnFocus: buttonRef.current`로 복귀 대상을 지정하세요. 결과 확인이 필요한 경우 재조회 버튼처럼 계속 사용할 수 있는 대상으로 지정합니다.
- 필수 입력·형식·날짜 범위 오류는 필드 근처에 둡니다. 조회 실패는 공통 모달로 알리고 화면에도 재조회 버튼과 함께 남깁니다. 성공 후 바로 이동하는 로그인·워크스페이스 생성은 추가 확인 없이 목적 화면으로 이동합니다.
- 광고·환불 등 처리 결과가 불확실한 오류는 모달을 닫아도 사라지면 안 됩니다. 복구 안내와 재실행 제한은 해당 페이지가 계속 관리합니다.

## 페이지별 적용 범위

| 화면 | 공통 모달 | 화면에 유지하는 내용 |
| --- | --- | --- |
| 로그인·회원가입 | 서버 오류, 주소 검색 실패, 가입 완료 후 로그인 이동 | 필수값·이메일·비밀번호 검증, 가입 완료 후 다시 로그인할 링크 |
| 워크스페이스·멤버 | 목록·상세 조회 실패, 생성·사용자 검색·초대 오류/결과, 멤버 내보내기 확인/완료 | 초대별 결과, 멤버 목록, 입력 오류 |
| Meta·네이버·아임웹 연결 | 진입·자산 조회 오류, 연결·저장 오류, OAuth 오류 및 필요한 구독 확인 | 저장 상태, 재인증·연결 재확인, 복귀 링크 |
| 광고·판매 성과 | 계정·상품·성과 조회 실패 | 날짜 검증, 데이터 표, 재조회·빈 목록 |

| 판매 플랫폼 상품 등록 | 등록 정보 조회 오류, 검토, 성공·부분 생성·실패 | 상품 ID, 이미지·상품 검증, 등록 여부 확인 및 재실행 제한 |
| 스마트스토어 주문·배송·환불·정산 | 이용 안내, 조회 오류, 처리 확인/오류 | 주문·클레임·결제 내역, 수령 동의, 결과 불명 확인·재실행 제한 |
| 고객 AI 스튜디오 | 목록·결과 조회, 업로드·생성·다운로드 오류, 결과 적용 완료 | 생성 진행·불명 상태, 미리보기, 채널 이동 링크 |
| 기술 지원·결제 | 요청·상태 오류, 이용 조건 설명, 결제 안내·결과 | 약관 동의 체크, 요청 목록, 결제 확인·재결제 제한 |
| 어드민 로그인·회원·워크스페이스·연결·지원·감사 | 인증·조회 오류, 공통 작업 확인 | 작업 모달 내부 입력 오류, 목록·상태 |
| 어드민 AI 샘플·카테고리 | 조회·분석·업로드·저장 오류, 삭제 확인, 저장 완료 | 이미지·필수값 검증, 분석 제안, 공개 상태 |

랜딩·404·준비 중인 플랫폼 페이지는 요청을 실행하지 않는 정적 안내 화면이므로 기존 페이지 안내를 유지합니다. 설명 문구 전체를 팝업으로 바꾸지 않으며, 동의가 필요한 약관과 작업에 영향을 주는 정보는 원래의 동의·확인 절차를 보존합니다.

`npm run test:modal`은 모달 순서, 중복 응답, 호출자 해제, 화면 이동, 늦은 응답, 중복 오류 확인 및 정리 시 Promise 완료를 검증합니다. 브라우저 검증에서는 실제 API를 모의 응답으로 대체하여 입력 유지·포커스·Esc·중복 제출·결과 불명 복구와 모바일 화면을 확인합니다.
